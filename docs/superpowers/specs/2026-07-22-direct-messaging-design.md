# 一对一私信功能设计

日期：2026-07-22

## 目标与范围

为已登录用户提供一对一私信。用户可从用户主页、存档作者信息和顶部“消息”入口进入会话；已登录用户可以主动发起私信。

首版支持：

- 文字消息；
- 一张聊天图片及可选附文；
- 会话列表、自己的未读数、历史消息游标加载；
- 前台 WebSocket 实时收取消息；
- WebSocket 不可用或页面长期后台时，HTTP 长轮询兜底；
- 网络恢复后的游标补拉。

首版不支持群聊、音视频、已读回执、撤回、搜索、拉黑、举报或消息编辑。未读数仅为收件人自己的状态，发送者不会看到“已读”。

## 前端体验与入口

新增需登录的 `/messages` 页面，放在既有 `DefaultLayout` 下：左侧显示会话列表，右侧显示当前聊天内容和输入区。没有会话时显示空状态。用户主页和文章作者区域为非本人显示“私信”按钮；该按钮跳转到 `/messages?peer={userId}`，但不创建空会话，首次成功发送时才创建。

`AppNavbar` 增加消息入口及全局未读数。进入会话后立即更新当前用户的查看位置并清除该会话的未读数；此行为不会推送或展示给对方。

样式直接复用 `src/assets/styles/variables.css` 与现有 Element Plus 覆盖：白色画布、GitHub 式灰色边框、现有链接蓝、绿色主按钮、既有间距和圆角令牌。不新增聊天专用色板。

前端新增：

- `api/messageApi.js`：会话、历史、发送、已查看、未读数和事件拉取接口；
- `stores/messages.js`：会话摘要、当前会话、未读总数、游标、连接状态和去重；
- `views/MessagesPage.vue`：页面组合和 URL 中 `peer` 参数处理；
- 会话列表、消息流、消息气泡、图片预览、输入框等小型组件；
- WebSocket/长轮询连接管理 composable。

## 后端数据模型

所有新实体遵循项目的混合 FK 规范：保存普通 `Long` 外键，不建立可写的 `@ManyToOne`。

### `direct_conversations`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_one_id`, `user_two_id` | 参与者 ID，创建时按数值升序规范化 |
| `last_message_id`, `last_message_at` | 会话摘要排序和列表展示 |
| `created_at`, `updated_at` | 应用层时间戳 |

`(user_one_id, user_two_id)` 设唯一约束，保证任意两名用户只有一个一对一会话；`last_message_at` 设索引以支持会话列表排序。

### `direct_messages`

| 字段 | 说明 |
|---|---|
| `id`, `conversation_id`, `sender_id` | 消息身份与归属 |
| `message_type` | `TEXT`、`IMAGE` 或 `IMAGE_WITH_TEXT` |
| `content` | 纯文本内容，可为空但图片消息必须有图片 |
| `image_key`, `image_thumbnail_key` | 由 `StorageService` 管理的对象键 |
| `image_width`, `image_height` | 图片展示尺寸 |
| `created_at` | 消息时间 |

对 `(conversation_id, id)` 建索引，支持 `beforeId` 游标倒序读取。消息 ID 也是客户端断线补拉和去重的游标。

### `conversation_read_states`

| 字段 | 说明 |
|---|---|
| `conversation_id`, `user_id` | 唯一的用户-会话阅读状态 |
| `last_read_message_id` | 当前用户最后已查看的消息 ID |
| `updated_at` | 最近查看时间 |

未读数由“该会话中 `id > last_read_message_id` 且发送者不是当前用户”的消息计算或按会话摘要批量聚合。该状态只返回给本人。

创建会话时同时创建两条阅读状态：首条消息的发送者将该消息设为自己的 `last_read_message_id`，接收者的值为空。历史数据或异常缺失的状态行按同样规则懒创建，空值表示“尚未查看任何消息”。

## REST 接口

| 接口 | 用途 |
|---|---|
| `GET /api/messages/conversations` | 分页取得会话摘要、对方公开资料、最后消息和我的未读数 |
| `GET /api/messages/conversations/{id}/items?beforeId=&size=` | 按游标取得历史消息 |
| `POST /api/messages/conversations/{targetUserId}/items` | `multipart` 发送文字和/或一张图片；必要时原子创建会话 |
| `POST /api/messages/conversations/{id}/read` | 更新当前用户的查看位置 |
| `GET /api/messages/unread-count` | 导航栏的断线兜底刷新 |
| `GET /api/messages/events?cursor=` | HTTP 长轮询事件接口 |

所有接口均要求登录。会话读写前必须确认当前用户是参与者；向自己、已停用用户或不存在用户发消息失败。

## 实时与降级机制

采用“WebSocket 优先、HTTP 长轮询兜底”的混合策略。

1. 打开私信页面并处于前台时，客户端通过 STOMP 建立 WebSocket；JWT 放在 STOMP CONNECT 头中，由服务端拦截器校验。
2. 连接仅订阅当前用户的私有事件：新消息、会话摘要变化和未读数变化。
3. 页面隐藏一段时间、连接失败或连续重连失败时，客户端关闭 WebSocket 并开始长轮询。
4. 长轮询请求携带最后同步消息游标。服务端以 `DeferredResult` 异步等待最多 25 秒；有更新立即返回，超时返回空结果，客户端随后续发请求。
5. 页面重新可见时停止长轮询、恢复 WebSocket，并基于消息 ID 补拉遗漏消息。

实时通道只通知“发生更新”及相关游标；消息实体始终经 REST 历史接口取得。数据库消息记录是唯一事实来源，因此网络切换、浏览器后台节流和通道切换不会造成已保存消息丢失。

消息事件由协议无关的后端分发器发布；WebSocket 订阅和长轮询等待器都是该分发器的消费者。当前单实例部署使用进程内事件分发即可；如以后横向扩展，再替换为 Redis 消息总线，不改变 REST 或前端协议。

## 图片存储、安全与异常处理

聊天图片键格式为 `messages/{conversationId}/{messageId}/...`，一律通过 `StorageService` 存取，因此本地存储和 COS 共用同一业务逻辑。支持 JPEG、PNG 和 WebP，单图不超过 10 MB；服务端验证扩展名、魔数、实际图片解码和像素尺寸，并生成适合消息流展示的缩略图。

文本只按纯文本渲染，经现有 XSS 清理；服务端限制空消息、最大长度、单图数量和发送频率。消息发送在持久化与存储失败时执行补偿删除，避免产生无数据库记录的聊天图片。

账号停用、身份失效、非参与者访问、非法图片和超出限流时，按项目既有 `ApiResponse` 与异常处理约定返回明确错误。前端在实时通道故障时展示重连状态，但不删除 REST 已确认的消息。

## 测试与验收

后端增加覆盖以下场景的单元和集成测试：

- 参与者排序与会话唯一约束；
- 只有接收者增加未读数，发送者没有已读回执；
- 非参与者不能读取、发送或标记会话；
- 文字和图片校验、上传失败补偿清理；
- WebSocket 和长轮询均能收到更新；
- 断线后按游标补拉不丢失、不重复、顺序正确。

前端当前没有自动化测试基础设施，首版以生产构建和双浏览器手工验收为准：两名用户分别登录，验证前台实时到达、后台降级、恢复连接、未读数和图片发送。后续如引入 Vitest，可将会话状态、去重与连接切换逻辑优先纳入单测。

## 非目标与后续扩展

群聊、客服、音视频、已读回执、撤回、搜索、拉黑、举报、消息编辑和跨实例消息总线均不属于首版。设计通过独立会话、消息、阅读状态和协议无关事件分发保留这些能力的后续扩展空间。
