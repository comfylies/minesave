# 上传页标签选择器设计

## 目标

将上传页的全量标签下拉框升级为适合大规模标签库的选择器，同时保留普通用户创建全站标签的能力。

## 已确认的产品规则

- 一篇存档最多选择 5 个标签。
- 普通登录用户可创建全站标签。
- 选择器采用“精选标签 + 搜索创建”模式。
- 标签搜索以 Meilisearch 为主，并在其不可用时降级到 MySQL 关键字匹配。

## 交互设计

标签输入框显示已选标签和 `已选数 / 5`。未输入关键词时，仅显示有限数量的管理员精选标签；不再加载全量标签。

用户输入至少两个字符后，前端以 300ms 防抖调用标签搜索接口。候选项先显示已有标签；仅当没有名称规范化后相同的标签时，显示“创建全站标签「关键词」”操作。达到 5 个标签后禁用继续选择和创建，并给出清晰提示。

创建成功后，新标签立刻作为已选标签和本地候选项显示，不等待搜索索引同步完成。服务端负责名称规范化、唯一性校验与并发创建冲突处理。

## 服务端搜索与降级

`GET /api/tags?q=` 保持为前端唯一入口，结果最多 10 条。

正常路径由 Meilisearch 标签索引返回匹配结果，排序优先级为：精确匹配、管理员标签、名称匹配度、使用热度（后续有热度字段时启用）。当 Meilisearch 连接失败、超时或返回不可用错误时，服务端记录告警并改用 MySQL 查询，不向上传页暴露基础设施故障。

MySQL 降级查询只返回最多 10 条，并按精确匹配、管理员标签和最近创建排序。它是可用性保障，不替代搜索引擎承担大规模模糊搜索。标签写入和同名去重始终以 MySQL 唯一约束为准；成功创建或更新标签后同步更新 Meilisearch 索引。

## 组件边界

- `TagSelector`：维护输入、已选标签、精选候选、远程候选和创建状态；不直接了解 Meilisearch 或 MySQL。
- `tagApi`：提供有限结果的搜索调用与创建调用。
- 标签服务：统一编排 Meilisearch 主搜索、MySQL 降级、创建去重及索引同步。
- 标签索引同步服务：负责单个标签增删改的索引更新，并在需要时支持重建。

## 错误与边界情况

- 搜索请求取消或过期时，旧结果不得覆盖最新输入。
- 创建时若另一请求已创建同名标签，返回既有标签并将其选中。
- 空白、超长与重复标签名由服务端校验；前端在提交前做相同的即时提示。
- Meilisearch 与 MySQL 都不可用时，显示可恢复的搜索错误；已选标签不丢失。

## 验证

- 后端测试：Meilisearch 正常、连接失败后 MySQL 降级、结果上限、同名创建冲突与索引同步。
- 前端验证：初始不拉取全量标签、300ms 防抖、最多 5 个、显式创建、创建后立即选中、快速输入不展示过期结果。
- 构建验证：运行后端相关测试与前端生产构建。
