# README 行级聚合批注设计

## 目标

在不改变现有“批注贴近 README 正文”的桌面布局前提下，消除密集批注卡片的重叠和遮挡。默认界面只展示行级摘要；用户主动点击后才查看完整批注内容。

## 范围

- 仅调整前端 README 批注的定位和展示；不改后端接口、`Comment` 数据结构或已存批注锚点。
- 桌面端是主要目标。现有移动端降级列表保持可用，但不为移动端新增独立的定位交互。
- 保留现有高亮、左侧色条、角色颜色、删除和回复信息。

## 默认展示

1. 按批注选区在浏览器中实际渲染出的第一行归组，而不是按 Markdown 段落归组。
2. 每个视觉行最多渲染一张右侧摘要卡，固定为单行高度，避免相互覆盖。
3. 摘要卡由三部分组成：选中文本前两个字符、该行第一条批注的单行省略内容、代表该行批注总数的数字徽标。
4. 数字是总数而非顺序编号；例如 `5` 表示该行有五条批注。
5. README 容器宽度变化时，使用 `Range.getClientRects()` 重新测量批注的视觉行并重新归组，保证窗口宽度变化后卡片仍与正文对应。

## 详情交互

1. 点击摘要卡的任意区域或数字徽标，进入该视觉行的详情模式。
2. 详情模式隐藏其他行的摘要卡，只显示当前行的完整批注列表；详情内容包含完整选中文本、批注全文、作者、角色、时间、回复和可用的删除操作。
3. 详情区域可滚动，长内容不截断，且不依赖 hover，因此鼠标离开、滚动或其他元素覆盖时不会消失。
4. 提供明确的“关闭/返回全部批注”操作。关闭后恢复所有行级摘要及原来的滚动位置。
5. 当前行的正文高亮与摘要卡使用现有 active 状态，方便建立对应关系。

## 组件职责

- `ReadmeRenderer.vue`：通过每条选区的 `Range.getClientRects()` 计算首个视觉行的 Y 坐标，按容差聚合为行级位置，并在容器尺寸变化时重新发出结果。
- `AnnotationPanel.vue`：将批注按接收的行组渲染；默认显示单行摘要，维护当前展开的行组并负责详情模式与关闭操作。
- `ArticlePage.vue`：继续转发位置数据和活动批注 ID；不引入新 API 或全局状态。

## 异常与兼容

- 无法重建 DOM Range 的旧批注维持现有单条列表降级路径，不阻断其他批注显示。
- 同一选区跨多行时，归属选区第一行，以保证用户点击其开始位置时获得稳定反馈。
- 通过 `ResizeObserver` 或现有 resize 回调合并到 `requestAnimationFrame` 后重算，避免滚动时连续布局计算。

## 验证

- 同一视觉行的多条批注只显示一张摘要卡，且数字为总数。
- 相邻行的摘要卡不重叠，长批注的详情完整可读。
- 打开一行详情时其他行隐藏，关闭后恢复。
- 调整 README 容器宽度后，行组与正文换行重新对应。
- 现有活动高亮、删除和窄屏降级行为保持正常。
