# 收藏页封面 URL 修复设计

## 目标

让“我的收藏”画廊中的存档卡片和游戏页、个人存档页一致，始终获得可直接加载的封面图与 360p 缩略图 URL。

## 根因

封面图数据库字段保存的是存储 key。普通存档列表会将该 key 转为公开 URL，并补充缩略图 URL；收藏列表绕过了这一步，直接返回 key，导致浏览器无法请求图片。

## 方案

在 `ArticleFavoriteServiceImpl#getFavorites` 中，映射 `ArticleListItemResponse` 后采用与 `ArticleServiceImpl` 相同的转换规则：

- 将 `coverImage` 的存储 key 转为公开 URL；
- 为存在的 360p 缩略图填充 `coverThumbnail`；
- 使用文章更新时间追加缓存参数，与其他列表保持一致；
- 没有封面或缩略图时返回 `null`，保留前端已有的占位图与原图降级行为。

为避免复制私有实现，将 URL 解析职责收敛为可被普通列表和收藏列表共同调用的服务级组件或可见辅助方法。不会变更数据库结构、前端接口形状或收藏业务规则。

## 验收与测试

新增针对收藏列表的回归测试，验证带封面文章的响应中：

- `coverImage` 是已解析的公开 URL，而非原始存储 key；
- `coverThumbnail` 是已解析的 360p 缩略图 URL；
- 缩略图不存在时仍保留可用的原图 URL。

运行该测试及相关后端测试，再进行后端编译验证。
