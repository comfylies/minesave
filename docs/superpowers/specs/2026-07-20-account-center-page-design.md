# 账户中心独立页面设计

## 目标

将用户主页中的账户管理功能拆为仅登录用户可访问的独立“账户中心”页面。公开个人主页继续展示用户资料和存档，不再包含资料编辑、头像或密码操作。

## 页面与导航

- 新路由为 `/account`，使用 `DefaultLayout` 并要求登录。
- 顶部用户下拉菜单新增“账户中心”入口；“个人主页”仍指向 `/users/:userId`。
- 账户中心使用前台内容容器，最大宽度约 900px，并保留页面左右留白；不复用管理后台的贴边侧栏。
- 宽屏采用两列：左侧 180px 账户导航，右侧白色内容面板。左侧包含“个人资料”“头像”“登录与安全”。
- 选择左侧项目时，仅切换右侧内容，不改变地址、不滚动页面。移动端将左栏改为可横向滚动的标签行。

## 视觉规范

- 对齐现有前台灰白配色：页面浅灰背景、白色内容卡、细灰边框、克制的 GitHub 蓝色主操作。
- 正文、输入框、按钮与导航统一使用 14px；页面标题为 24px，区块标题为 16px。
- 使用紧凑的 GitHub 风格间距、圆角和控件高度，避免管理后台的强色块、宽大标题或贴边布局。

## 功能边界

### 个人资料

保留已有昵称、个人简介、手机号编辑能力和服务端校验。保存后同步 Pinia 中的当前用户信息。

### 头像

- 保留 JPEG、PNG、WebP 和 2 MiB 限制，以及存储抽象 `StorageService`。
- 后端从原图中心裁剪为正方形，生成 JPEG 三个版本：主图 `180x180`、半尺寸 `90x90`、四分之一尺寸 `45x45`。
- 主图 URL 保持在现有 `avatarUrl` 响应字段中，额外返回缩略图 URL 字段供导航栏等紧凑位置使用。
- 替换或删除头像时，三个托管对象都必须一并清理；若生成或存储失败，清理本次已写入的对象并保留原头像。

### 登录与安全

保留现有“当前密码 + 新密码 + 确认密码”的改密流程。密码修改成功后注销并跳转登录页，行为不变。

## 测试与验证

- 为头像服务增加测试：验证居中裁剪后的主图尺寸和三份对象键、旧的三份对象清理、写入异常回滚清理。
- 为用户响应测试缩略图 URL 映射（如项目现有测试结构允许）。
- 前端完成生产构建，并在本地浏览器验证：导航入口、三项内容切换、资料保存、头像选择入口和密码表单。
- 不在本次改动中修改 `CLAUDE.md`。
