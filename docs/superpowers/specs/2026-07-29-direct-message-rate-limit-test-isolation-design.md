# 私信限流测试隔离设计

## 目标

消除私信集成测试之间共享内存限流状态造成的偶发失败，同时保留生产环境的私信突发限流与封禁策略。

## 根因

`DirectMessageServiceTest` 使用 Spring 上下文中的单例 `RateLimiter`，所有测试都以相同 IP 发送消息。数据库事务会回滚消息记录，但不会回滚限流器内存计数；连续测试超过 5 秒 5 条的突发上限后，后续测试被封禁 30 秒。

## 方案

- 在 `RateLimiter` 增加一个仅清空内存计数器与 IP 封禁记录的公开方法；
- 在 `DirectMessageServiceTest` 注入该限流器，并在既有 `@BeforeEach` 中清空状态；
- 不改动生产请求路径、限流键、5 秒 5 条突发阈值、30 秒封禁和分钟级发送限制。

## 验收

连续运行 `DirectMessageServiceTest` 时，各测试不再因其他测试的发送次数被限流；服务级私信限流单元测试继续覆盖生产规则。
